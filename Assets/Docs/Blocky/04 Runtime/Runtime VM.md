# Runtime VM

Source: [[Welcome|TDD §6]]. Status: **done** — scheduler, thread, `IBlockOp`, the full v1 control catalog, all 7 motion/looks ops (Milestone 7 added the remaining 6 — see [[06 Block Catalog/Block Catalog|Block Catalog]]), `TriggerBroker`, and `ObjectProgramRunner` (Milestone 6). `ProfilerMarker`s now instrument `Tick`/`Step` (Milestone 7, TDD §11.3). A program runs end-to-end from a real scene.

**Naming note:** the TDD's "Thread" is implemented as `VmThread` to avoid colliding with `System.Threading.Thread` — same concept, different name.

**How looping actually works (this wasn't fully specified in the TDD, see [[09 Decisions/Decisions#ADR-002|ADR-002]]):** a C-block op (e.g. `control.repeat`) pushes a `Frame{OwnerPc, ExitPc, Counter}` on first entry and jumps into its branch. The VM's `Step` doesn't know or care what kind of block owns a frame — every step it just asks "has pc reached the top frame's ExitPc?" and if so hands control back to `OwnerPc` without executing anything. It's the *op itself*, re-invoked at its own pc, that decides whether to loop again (jump back into the branch) or pop the frame and fall through to `ExitPc`. This is also where the loop-yield rule lives: the VM forces one frame yield per lap that never yielded on its own, so a body with zero yielding instructions still can't hang a game frame.

**Custom blocks are frames too** ([[09 Decisions/Decisions#ADR-029|ADR-029]]). `run [name]` pushes a *call* frame (`Frame.IsCall`) whose `ExitPc` is the end of the definition's script and jumps to its first block. When pc reaches that exit, `Step` itself pops the frame and continues at the block after the `run` (`VmThread.ReturnFromCall`) — the one case where control does not go back through the owning op, because with recursion the same `run` block can be arrived at anew while its own frame is on top, and only the scheduler knows it is returning. A definition's code lies outside the calling script's range, so a thread ends at `VmThread.EndPc` — its own `ExitPc`, or inside a call, the definition's exit — instead of at `ExitPc`. Each call keeps its three input values on a small per-thread array (made on the first call), so `input a` reads the innermost call's value.

**So is the mouth of `as [object]`** ([[09 Decisions/Decisions#ADR-042 — `as [object]` is a frame that carries the object the blocks act on|ADR-042]]). `control.as_object` pushes a frame that carries a `GameObject` (`Frame.As`: `HasActsOn`, `ActsOn`), and `OpContext.Target` / `SlotContext.Target` return `VmThread.ActsOn` — the innermost such frame's object, else the thread's own `Target`. Every op already read its object through `ctx.Target`, so none had to change; nesting, a custom block run from inside, and Step back (frames are saved whole) all follow from the frame stack. The thread itself stays its own object's: pausing, stepping and stopping are keyed on `VmThread.Target`, and an op that means the script's own object whatever it is inside (`stop [other scripts on this object]`) reads `ctx.Thread.Target`. A name no object answers to skips the mouth (one warning per run); an object destroyed while its blocks run is unwound by the scheduler before the next block (`VmThread.SkipAsIfObjectGone`: frames above it are popped, a call's `EndPc` restored, the mouth's timers cleared, pc set to the block's exit).

## Why a VM
Async recursion (`UniTask Execute(BlockNode, ...)`) is the obvious design and the wrong core: state lives in C# stack frames (uninspectable/unpausable), call depth = user nesting depth (uncontrolled stack overflow), async state machines cost per-block even pooled, infinite loops deadlock the frame per-op instead of centrally, cancellation is scattered. A flat instruction array + explicit thread state avoids all five — this is how Scratch itself is built.

## Shapes
- `Instruction` (readonly struct): Opcode, ParamOffset, ParamCount, JumpA/B, SourceNodeId (debug)
- `Thread` (pooled in the TDD, a plain allocation so far): Program, Target, Pc, Frames[] (16 to start, doubling up to `MaxNestingDepth` = 256, loops and custom-block calls counted together), EndPc, CallDepth, the calls' input values, Scratch[], State, WakeAt, Generation
- `OpResult`: Continue / YieldFrame / Retry / Jump / Fail
- `IBlockOp.Execute(ref OpContext ctx)` — `OpContext` is a `ref struct`, no boxing/closures/allocation
- Dispatch: `opTable[instruction.Opcode].Execute(ref ctx)` — one array index, one interface call

## Execution semantics (product decisions, not details — TDD §6.4)
- Loop yield rule: every iteration yields ≥1 frame if the body executed no yielding instruction
- Instruction budget: default 10,000/tick, forces yield + warns naming the offending block
- Retrigger: default `RestartOnRetrigger` (resets pc, bumps Generation); overridable per-trigger to `IgnoreWhileRunning`/`AllowConcurrent`
- Tick order: `(objectRegistrationIndex, stackIndex)`, stable per object lifetime; threads started mid-tick begin next tick
- Physics-affecting ops write to a deferred queue flushed in `FixedUpdate`
- Destroyed target → scheduler kills its threads before stepping; ops never need destroyed-object guards. The object of an `as [object]` block destroyed under it only ends that block's mouth — the script carries on after it
- `StopAll` clears all threads; disabling does not auto-resume on re-enable. `StopAllThreads()` and `StopOtherThreadsOn(target, except)` are the in-tick versions behind `control.stop` — they mark threads `Done` without touching the lists, which is the only safe thing to do from inside a running block.
- Ops read their inputs through `OpContext.GetNumber` / `GetText` / `GetBool`, never `Params[i].Number` — that is what lets a reporter sit in any white oval ([[09 Decisions/Decisions#ADR-021|ADR-021]]). `SlotEvaluator` resolves a slot to a `BlockValue`, running an `IConditionOp` or an `IValueOp` as needed, and coercing between them
- A thread ends at **its own stack's** exit pc (`VmThread.ExitPc`, from `CompiledProgram.StackExitPoints`), not at the end of the program's instruction array — every stack is emitted into one shared array, see [[09 Decisions/Decisions#ADR-019|ADR-019]]. Inside a custom block the bound is the definition's exit (`EndPc`). A script with no blocks gets no entry point at all (-1, like a loose stack): it has no code, so its entry pc was the *next* script's, and a thread identified by that pc ran — or ended — the wrong script
- A custom block that runs itself waits one frame first (Scratch's rule), and past `MaxNestingDepth` a `run` does nothing — so a recursion that never stops slows down and then unwinds, instead of hanging or overflowing anything
- **What game code hears** ([[09 Decisions/Decisions#ADR-033|ADR-033]]): `ThreadStarted` when a pending thread goes live, `ThreadFinished` for a started thread that ended *by itself* (`VmThread.EndReason`: `Completed`, `StoppedByBlock`, `Failed` — null when something outside ended it), and `AllThreadsFinished` when such an ending leaves nothing running or pending. Reported after the thread lists are settled, each listener in its own `try`. `BlockyEvents` turns them into the public events.
- The **timer** (`Timer`, `ResetTimer()`) runs on the script clock `Now`, so it pauses with the scene, scales with speed, and is saved and restored by Step back. `SlotContext.Timer` is how `timer > n?` reads it; `OpContext.Scheduler` is how `reset timer` and `stop` reach the scheduler at all.

## Playback controls (learning aids)
Scene-wide, in `VmScheduler` — see [[09 Decisions/Decisions#ADR-012|ADR-012]]:
- `Pause()` / `Resume()`: while paused, `Tick` returns before advancing the clock, so waits and timed blocks keep their place. Scripts triggered while paused wait in the pending list.
- `Step()`: pauses, then every live script finishes or starts exactly one block and parks at the start of the next one (`VmThread.StepBudget` / `StepParked`; `IsMidBlock` = last result was `Retry` at this pc). `IsStepping` stays true until every thread has parked or finished.
- `TimeScale` multiplies `dt` (the run bar sets 1–4; see [[09 Decisions/Decisions#ADR-013|ADR-013]]).
- `SaveMoment()` / `RestoreMoment(moment)`: every thread's progress (`ThreadMoment`: pc, the live frames, the custom-block calls and their inputs, scratch, state, wake time, active/resume pc) and the clock. Restore writes back into the **same** `VmThread` objects, brings back threads that finished since, ends ones started since, and leaves everything paused.
- `FindLive(target, program, entryPc)` / `StopWhere(target, program)`: how `ObjectProgramRunner` finds and stops its threads. It keeps no thread list of its own, so restored threads are still recognised.
- `VmThread.ActivePc` / `ActiveNodeId`: the block started most recently. `RunningBlocks.Collect(scheduler, target, list)` lists it per object, allocation-free.
- Finished threads are removed at the end of every tick (`RemoveAll` with a cached predicate).
- **`Playback`** (`BlockyRuntime.Playback`) holds the run bar's commands: `Go`, `Stop`, `ResetWorld`, `Pause`/`Resume`, `StepForward` (records a moment of scripts + objects + "Play clicked" state, fires `TriggerBroker.FireStepAll` so every script that isn't running starts, then `Step`; ignored while a step is finishing), `StepBack` (restores the last one; 200 kept), `SetSpeed` (1–4), `ForgetSteps`. `Stop` = `StopAll` + re-arm `when Play clicked` (so Go / Step ▶ after Stop run every script again). `ResetWorld` = `Stop` + `WorldSnapshot.RestoreAll`. The step history is dropped on Resume/Go/Stop/Reset and on any program edit.

## Async adapter
`IAsyncBlockOp.ExecuteAsync` behind `AsyncOpBridge` — starts on first execution, returns `Retry` until done (one allocation at start, zero per frame). Cancellation tokens pooled per thread, linked to `Generation`. This is the **only** place UniTask is used (see [[00 Overview/Goals and Non-Goals|dependencies]]).

## Trigger system
`TriggerBroker` typed channels, subscribe on enable/unsubscribe on disable. `WhenLookedAt` is one shared camera raycast per frame compared against the listener set — never per-object. `OnClicked` is the same idea for `when clicked`: one raycast per frame, on the press edge only, through `BlockyInput` so a press on the editor never counts; the runner treats a hit on a child collider as a hit on itself. `OnBroadcast` carries a name and nothing else — listeners match it themselves (case- and space-insensitively), so the broker never has to know which messages a program uses.

`OnCloneStarted` is raised by `create clone` itself, once the copy exists and its runner has been initialised by hand — a clone that heard its own hat a frame late would never start ([[09 Decisions/Decisions#ADR-026|ADR-026]]).

**A game can take the channels over** ([[09 Decisions/Decisions#ADR-041 — A game can host Blocky: the game owns the flow, Blocky keeps its defaults|ADR-041]]). `BlockyRuntimeTicker` has a switch per thing it does by itself — `FirePlayClickedOnStart`, `AttachSavedPrograms`, `PollKeyboard`, `PollLookedAt`, `PollClicked` — all on by default; the scheduler ticks whatever they say. With a channel off the game raises it: `RaiseLookedAt(target)` (its own gaze: a reticle raycast with a dwell timer), `RaiseClicked(target)`, `FirePlayClickedFor(go)` / `FireGoClicked(go)` from its own Play button. Saved programs are attached at the top of the ticker's `Start`, no longer in `Awake`, so a ticker added from code can be configured before it acts. `BlockyInput.AddPointerOverUiCheck` lets any number of interfaces say "the pointer is over me", so a press on the game's own uGUI is neither `mouse down?` nor a click on the object behind it; the workspace registers its own check the same way.

**Where a runner's program comes from**, in order: one handed over by code (`SetProgram(ObjectProgram)`, or `SetProgramAsset`), else one saved for the object in `BlockyStorage.Current` (the save files by default, the game's own `IProgramStorage` if it set one), else the scene's asset. `SetProgram` keeps one in-memory asset per runner and, on a running runner, stops its scripts and compiles the new program at once — the in-game editor's hot reload goes through it too.

**Reset's start can move** ([[09 Decisions/Decisions#ADR-043 — An object's look is every renderer under it, and Reset's start can be moved|ADR-043]]). `WorldSnapshot.Capture` records an object the first time only; `Recapture(go)` / `RecaptureAll()` make its current state the start (a game calls it when the learner has placed the object), `Forget(go)` stops tracking it, and `CaptureDriven(driver, driven)` — called by `as [object]` — ties an object to the one whose script moves it, so `RestoreObject(driver)` and `SaveMoment(driver)` cover both. A moment holds, per renderer under the object, its materials, their colors and a sprite's tint; a material a renderer had when first seen is never recolored.

One channel is **not** tied to a hat: `OnStepAll`, which every compiled non-loose stack subscribes to as well as its own — except a custom block's `define` script, which only a `run` block ever starts. `Playback.StepForward` fires it, so Step ▶ can walk a script whose trigger the learner cannot produce while the scene is frozen (a key press, a bump, a look). `ObjectProgramRunner.FireForStep` starts such a stack only when `VmScheduler.FindLive` finds nothing running it — stepping ignores `RetriggerPolicy` on purpose. See [[09 Decisions/Decisions#ADR-015|ADR-015]].
